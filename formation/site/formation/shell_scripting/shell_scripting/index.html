Un Shell et le Scripting

Ce chapitre présente la notion de shell et le terme scripting

Les Shell

Qu’est ce qu’un shell ?

Un peu d’histoire et de notion importante:

Extrait wikipédia: Bourne shell

Le Bourne shell ou bsh (ou encore simplement sh dans de nombreuses versions d’UNIX) est un shell Unix. C’est le shell par défaut de la version 7 d’Unix ; dans les versions antérieures d’UNIX, le nom sh désigne le Thompson shell, et dans certaines versions actuelles, il désigne le Korn shell.

Le Bourne shell a été programmé par Stephen Bourne (d’où le nom) d’AT&T Bell Laboratories et a fait son apparition pour la première fois en 1977 sur la version 7 d’Unix qui était distribuée aux universités et académies. Il est resté depuis cette époque le shell par défaut pour les comptes Unix. Le fichier exécutable du Bourne shell ou de tout autre shell compatible se trouve à l’emplacement /bin/sh sur la plupart des systèmes Unix et est toujours le shell par défaut du compte root sur de nombreuses implémentations d’Unix.

Avec son système de tubes connectant la sortie d’une commande à l’entrée d’une autre, il permet d’écrire des scripts complexes à partir de commandes simples. Une version améliorée de ce shell est le Bourne-Again shell.

Extrait wikipédia: UNIX

Unix, officiellement UNIX, est une famille de systèmes d’exploitation ouverts, multitâche et multi-utilisateur. Unix est dérivé de l’Unix d’origine créé par AT&T, le développement de ce dernier ayant commencé dans les années 1970 au centre de recherche de Bell Labs mené par Kenneth Thompson. Il est composé d’un noyau (qui assure la gestion de la mémoire, des entrées et sorties de bas niveau, l’enchaînement des tâches), d’un interpréteur ou superviseur (le shell), et de nombreux petits utilitaires, accomplissant chacun une action spécifique, commutables entre eux (mécanisme de « redirection ») et appelés depuis la ligne de commande.

  • Les systèmes Unix sont des systèmes ouverts, multitâches et multi-utilisateurs.

  • Les systèmes Unix ont en commun plusieurs concepts développés dès les premières versions d’Unix aux laboratoires Bell.

Extrait wikipédia: POSIX

POSIX ((Portable Operating System Interface) et le X exprime l’héritage UNIX) est une famille de normes techniques définie depuis 1988 par l’Institute of Electrical and Electronics Engineers (IEEE), et formellement désignée par IEEE 1003. Ces normes ont émergé d’un projet de standardisation des interfaces de programmation des logiciels destinés à fonctionner sur les variantes du système d’exploitation UNIX.

Le terme POSIX a été suggéré par Richard Stallman, qui faisait partie du comité qui écrivit la première version de la norme. L’IEEE choisit de le retenir car il était facilement mémorisable[1],[2].

Un shell est un interpréteur de commande d’un système UNIX. C’est un binaire qui ne fait pas partie du noyau, c’est une interface entre l’utilisateur et le système.

IA réponse: Le bsh fait-il parti du noyau de debian ?

Non, le shell bsh (Bourne shell, souvent désigné par sh) ne fait pas partie du noyau (kernel) des systèmes UNIX/Linux. Voici les clarifications :

  1. Rôle du noyau (kernel)

Le noyau est le cœur du système d’exploitation. Il gère :

 Les processus et la mémoire,

 Les pilotes matériels (disques, réseau, etc.),

 Les appels système (syscalls).

Le shell, quant à lui, est un programme utilisateur qui permet d’interagir avec le noyau via des commandes.

  1. Le shell est un outil en espace utilisateur

    Le shell (comme sh, bash, csh, etc.) est un exécutable situé dans /bin ou /usr/bin.

    Il est lancé après le démarrage du système, une fois le noyau initialisé.

    Exemple : /bin/sh (Bourne shell) ou /bin/bash (Bourne-Again shell).

  2. Interaction shell/noyau

Le shell utilise des appels système (syscalls) pour communiquer avec le noyau. Par exemple :

Quand vous exécutez ls, le shell appelle fork() pour créer un nouveau processus, puis exec() pour lancer /bin/ls.

Le noyau gère ensuite l'exécution de ls et renvoie le résultat au shell.

  1. Cas spécifique de bsh

    bsh est une ancienne abréviation pour le Bourne shell (sh), le shell historique d’UNIX.

    Il n’est pas intégré au noyau, mais est un programme standard fourni avec le système UNIX.

  2. Exemple concret sous Linux

    Le noyau Linux est typiquement situé dans /boot/vmlinuz-….

    Le shell bash est installé séparément dans /bin/bash.

    Si vous supprimez /bin/bash, le noyau continue de fonctionner, mais vous perdez l’accès au shell.

Il en existe plusieurs :

  • Bsh (sh)
  • Bash
  • Ksh
  • Csh

Le BASH

Ici nous allons nous concentrer sur l’interpréteur BASH (Bourne-Again Shell ) qui est le plus rependu sur les systèmes Linux.

Le shell est appelé langage de programmation, mais n’est qu’une succession d’instruction, qui grâce à des commandes simples permettent:

  • L’utilisation de variables
  • D’exécution conditionnelle
  • Création de fonctionnalité pour des répétitions de commandes

Le scripting shell, peu import l’interpréteur choissi, n’a pas besion d’être compilé. Il est préférable de parler de langage de scripting plutôt que langage de programmation.

Système d’exploitation debian

Nous allons travailler sur le système d’exploitation DEBIAN avec l’interpréteur de commande BASH.

Debian est un système d’exploitation GNU/Linux qui est un système UNIX qui répond donc aux normes POSIX.

BASH est le shell de base de Debian, lors d’une installation normal. C’est une version améliorée de Bsh (autrement dis sh) le shell par default des systèmes UNIX.

Un script

Qu’est ce qu’un script ?

Comme expliqué précédemment un script est une succession de commande agrémenté de variable, d’exécution conditionnelle ainsi que de fonction.

Un script doit être:

  • Fiable:

      - Son fonctionnement est irréprochable même en cas de mauvaise utilisation

  • Commenté:

      - Son code est annoté pour en faciliter la relecture et les futures évolutions

  • Lisible:

      - Le code est indenté à bon escient, les commandes sont aérées, …

  • Portable:

      - Le code fonctionne sur tout système Linux, gestion des dépendances, gestion des droits, etc.

Un script doit être correctement nommé:

  • Pas de nom de commande existante
  • Caractères alpha-numériques uniquement
  • extension en .sh (exeption : si le script doit devenir une commande)
  • Doit posséder un cartouche (nom de l’auteur, date d’ecriture, commentaire d’explication, version)
  • Doit posséder un shebang: #!/bin/bash (doit être absolument la première ligne du script)

Script d’exemple: cartouche.sh


#!/bin/bash
#
#auteur: Emile Zola
#Date: 01/01/1900
#version: V0
#Commentaire:
#Ce script montre l'exemple d'un cartouche il n'execute aucune commande
