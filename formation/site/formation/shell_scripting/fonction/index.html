Les fonctions

Les fonctions permettent l’optimisation du script en automatisant une/des tâche(s) répétitive(s). Elles permettent une meilleur structuration du code.

0- Syntaxe

1- Les fonctions

Une fonction est un enchaînement de commande que l’on peut appeler lorsque necéssaire. Elle permet d’être appelé plusieurs fois sans avoir à réécrire une séquence de commande exécuté plusieurs fois.


#!/bin/bash

ma_fonction() {
    echo "Appel de la fonction: Le chiffre est supérieur ou égal à 5"
}

read -p "Entrez un chiffre entre 1 et 9: " chiffre

# Vérification améliorée de l'input
if [[ ! "$chiffre" =~ ^[1-9]$ ]]; then
    echo "Erreur: Entrez uniquement un chiffre entre 1 et 9" >&2
    exit 1
elif (( chiffre < 5 )); then
    echo "Le chiffre choisi ($chiffre) est inférieur à 5"
elif (( chiffre >= 5 )); then
    ma_fonction
fi

Exemple: fonction/fonction_1.sh

2- Break / Continue

Lorsque vous créer une fonction avec plusieurs conditions, il existe deux commande très importante afin de contrôler les opérations conditionnelles au sein de la fonction.

  • break: permet de sortir d’une boucle lorsqu’une condition est vrai.
  • continue: permet de stopper la suite d’une boucle en passant à la prochaine itération.
Ces deux options ne sont pas uniquement utilisable dans une fonction. 

#!/bin/bash

# Définition de la fonction
traiter_nombres() {
    local compteur=0  # Variable locale pour compter les nombres traités
    local nombre

    echo "Début du traitement des nombres..."

    for nombre in {1..20}; do  # Boucle de 1 à 20
        # Condition pour 'break' - sortie de boucle
        if (( nombre > 15 )); then
            echo "⚠️  Nombre supérieur à 15 détecté : $nombre - arrêt du traitement !"
            break
        fi

        # Condition pour 'continue' - sauter une itération
        if (( nombre % 2 == 0 )); then
            echo "↪️  Nombre pair ignoré : $nombre"
            continue
        fi

        # Traitement du nombre impair
        echo "✅ Traitement du nombre impair : $nombre"
        ((compteur++))
    done

    echo "Total de nombres impairs traités : $compteur"
}


# Appel de la fonction
traiter_nombres

echo "Script terminé !"

Il faut comprendre que l’exécution d’un script correspond à exécuté une commande qui exécute plusiseurs commande jusqu’à la fin du script.

  • Le script peut s’arrété à cause de:

    • D'une erreur

3.1- L’exécution d’un script

Que se passe-t-il quand on exécute un script ?

Il faut s’intéresser au processus d’un système GNU/Linux.

Lors du démarrage de mon système d’exploitation l’orchestateur de processus est lancé. C’est un binaire exécuté par le noyau /sbin/init. Etant le tout prémier processus démarrant il prend le PID 1 (Processus IDentification)

Une fois mon système démarré, l’utilisateur lance son application de terminal console. N’ayant pas encore l’information de quel interpréteur de commande l’utilisateur utilise le système va utilisé le shell par default des systèmes UNIX: /bin/sh (bsh) pour exécuté le binaire de l’application de terminal. /bin/sh -c alacritty

Le binaire de l’application alacritty est donc exécuté, il obtient donc son propre numéro de processus. Lors du démarrage de l’application de terminal le binaire va lire les paramètres utilisateur dont le chemin du shell choissi. Ici /bin/bash est exécuté dans le terminal ce qui affiche l’interpréteur de commande bash et démarre son propre processus.

Une fois dans le terminal l’utilisateur exécute son script shell qui possède un shebang précissant le type de code à exécuté. Etant un script shell bash avec #!/bin/bash une autre instance de bash va être lancé par bash avec son propre PID.

Chaque étape dépent de la précédente et se raccorde toute entre elles grâce au PID qui leur son propre et les PPID qui est le procéssus auquel il est lié.

3.2- Orchestrateur de processus et histoire

Comment connaître son orchestrateur de processus ?


$> ps -p 1 -o comm=         # Cherche quelle bianire est mon orchestrateur de processus
systemd

Rôle principal du processus 1 (init)

  1. Initialisation du système :

    • Il est responsable du démarrage des services système, des scripts d’initialisation, et de la configuration de l’environnement utilisateur.
    • Il gère les niveaux d’exécution (runlevels pour SysVinit) ou les cibles (targets pour systemd).

  2. Parent de tous les processus :

    • Tous les processus utilisateur descendent de PID 1. Si un processus devient orphelin, il est “adopté” par init.

  3. Gestion des arrêts et redémarrages :

    • Il orchestre l’arrêt propre du système (ex: shutdown, reboot).

Evolution sous Debian

Debian a transitionné de SysVinit (système historique) à systemd (modern) depuis Debian 8 (Jessie, 2015). La binaire /sbin/init peut donc être associée à l’un ou l’autre selon la version.

1. Cas de SysVinit (anciennes versions de Debian)

  • Fonctionnement :

    • /sbin/init est le binaire SysVinit.
    • Il lit le fichier /etc/inittab pour déterminer le runlevel par défaut (ex: 3 = mode multi-utilisateur, 5 = mode graphique).
    • Exécute les scripts dans /etc/rc.d/rcX.d/ (où X est le runlevel) pour démarrer/arrêter les services.

  • Structure des runlevels :

    # Exemple de runlevel
0 → Arrêt
1 → Mode mono-utilisateur (maintenance)
2 → Multi-utilisateur sans réseau
3 → Multi-utilisateur avec réseau (mode texte)
5 → Mode graphique (Xorg)
6 → Redémarrage
2. Cas de systemd (Debian moderne)

  • Fonctionnement :

    • /sbin/init est un lien symbolique vers systemd (vérifier via ls -l /sbin/init).
    • Systemd utilise des unités (fichiers .service, .socket, etc.) et des cibles (targets) pour gérer les dépendances et paralléliser le démarrage.
    • Exemple de cibles :
      • multi-user.target → Équivalent du runlevel 3.
      • graphical.target → Équivalent du runlevel 5.

  • Avantages de systemd :

    • Démarrage plus rapide grâce au parallélisme.
    • Journalisation centralisée avec journalctl.
    • Gestion dynamique des services (activation à la demande).

RAPPEL

Il faut comprendre que l’exécution d’un script correspond à exécuté une commande qui exécute plusiseurs commande jusqu’à la fin du script.

  • Le script peut s’arrété à cause de:

    • D'une erreur
    • Instruction d'arrêt forcé (CTRL + C / CTRL + D)
    • Il a terminé toute ses instructions.

#!/bin/bash
#

input=${1:?Entrez le nom d un paquet}


# Vérifie si l'utilisateur est root (retourne un code)
check_root() {
    if [ "$(id -u)" -eq 0 ]; then
        echo "Vous êtes root."
        return 0
    else
        echo "Vous n'êtes pas root."
        return 1
    fi
}

# Vérifie un package et quitte le script si absent
check_package() {
    local package="$1"
    if ! command -v "$package" &> /dev/null; then
        echo "Erreur: $package est requis mais non installé."
        return 1
    else
        echo "$package est installé."
        return 0
    fi
}

# Affiche un message en rouge
error_message() {
    local msg="$1"
    echo -e "\033[31m$msg\033[0m"
}

# Fonction principale
main() {
    check_root
    local is_root=$?

    # Avertissement si non-root
    if [ "$is_root" -ne 0 ]; then
        error_message "Attention : Certaines fonctionnalités nécessitent root."
        exit 1
    fi

    # Vérification critique de curl
    check_package "$input"

    local is_installed=$?

    if [ "$is_installed" -ne 0 ]
    then
        # Suite du script
        echo "Téléchargement en cours..."
        apt install -y "$input"
    fi
    # curl ... (exemple)
}

# Démarrage du script
main

Les commandes exit et return permettent d’intéragir avec le conportement du script de 2 manières différentes.

  • exit permet d’arrété le script en attribuant un code de fin d’éxécution comme pour les commandes. Effectivement comme vu précédemment /bin/bash est une commande qui possède (ou pas) des paramêtres, des arguments et donc des entrés/sorties standards. Exit termine le processus en cours. Dans la norme un code retour de bash est 0 lorsque exécuté correctement et un autre chiffre en cas d’exécution incorrect (à vous de définir vos codes d’erreurs). 1 est quand à lui réservé à une mauvaise utilisation du script peu importe l’erreur.

  • return permet de donner un état de fin d’éxécution d’une fonction. Cela équivaut à attribuer un code de fin d’exécution à une fonction comme si s’était une commande. Vous pouvez donnez n’import quel valeur après un return mais souvent on l’utilise de manière booléen dans une condition: 0 = vrai et 1 = faux.
