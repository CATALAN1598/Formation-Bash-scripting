Les opérations conditionnelles

Afin de réalisé des opérations algorithmiques, il est possible d’exécuté des opérations conditionnelles. Elles ont pour but d’effectuer des vérifications afin de manipuler des commandes ou des variables.

Il en existe plusieurs:

0- La commande test

Avant de voir les différentes opérations conditionnelles il faut voir la commande test.

La commande test est déployé par défaut sur DEBIAN: man test

Dans un script elle est représeté par [ vérification ]

Commande TEST

Les espaces sont obligatoire !

Avant de voir le fonctionnement de la commande test, nous allons faire un focus sur:

  • Les codes retours.
  • Les redirections
  • Les pipelines de redirection

0.1- Les codes retours des commandes

En bash lorsque vous exécutez une commande elle possède un code retour.

  • 0: lorsque la commande c’est exécuté correctement avec un résultat attendu
  • 1: lorsque la commande c’est exécuté avec un mavaise résultat
  • autre lorsque la commande obtient un résultat particulié

Les codes retours négatifs

Ce n’est pas par ce que le code est autre que 0 que la commande c’est mal exécuté !

Une code 1 peut vouloir dire “commande correctement exécuté mais résultat attendu incorrect”

Vous trouverez souvent la correspondance des codes retours des commandes dans les manuels de commande: On oublit pas RTFM !!!

  • Exemple: pour la commande ls

Extrait de man ls


   État de fin d'exécution :
       0      si OK,

       1      si problèmes mineurs (par exemple, impossible d'accéder à un sous-répertoire),

       2      si erreur grave (par exemple, impossible d'accéder aux paramètres de la ligne de commande).

Voir code retour de grep

0.2- Les standards et les redirection

Avant de commencé il faut comprendre qu’est ce qu’une commande:

Lorsqu’une commande est exécuté elle attend quelque chose en entré, appeler stdin (standard input), et repond une sortie sous deux formes possible stdout (standard output) et stderr (standard error)



                |-----------|
    --stdin-----|    CMD    |-----stdout---
                |-----------|
                      |
                      |
                    stderr
                      |

Chaque standard possède un ID.

  • stdin : 0
  • stdout : 1
  • sterr : 2

Il est possible d’intéragir avec ces différents standard.

Par exemple:


echo "toto" > toto.txt

La commande echo à en stdin (0) toto et redirige la sortie standard (stdout id:1) dans toto.txt

Il faut lire:


echo <0 "toto" 1> toto.txt

On envoie la valeur toto dans l’entré standard de la commande echo puis on redirige la sortie standard de la commande echo "toto" dans le fichier toto.txt

Autre exemple:

Le fichier toto n’existe pas


ls -l toto > log.txt 2>&1

cat log.txt
ls: impossible d'accéder à 'toto': Aucun fichier ou dossier de ce type

La commande ls -l à en entré standard toto la sortie standard de la commande est envoyé dans log.txt en redirigeant 2, la sortie d’erreur, dans la sortie standard 2>&1.

Donc le contenut de log.txt contient les informations de la sortie d’erreur envoyé dans la sortie standard qui est elle même redirigé vers le fichier log.txt

0.3- Les pipelines de redirection

Il faut également voir les pipelines de redirection de commande, nous allons en voir 3:

  • cmd 1 | cmd 2 : La redirection de la sortie de commande 1 vers commande 2
  • cmd 1 && cmd 2 : ET Si commande 1 correctement terminé (code d’erreur) exécute commande 2
  • cmd 1 || cmd 2 : OU Si commande 1 terminé avec une erreur (code d’erreur) exécute commande 2
Les pipes

Les pipes perment de redirigé la sortie standard d’une commande vers une autre.


ls -l | grep '.sh'

                       |                                        |
                       |                                        |
                     stderr                                   stderr
                       |                                        |

Retour sur la commande test

Vous devez vous prendre en compte les codes retours.


$> test 1 -eq 1     # Test si 1 equivaut à 1

$> echo $?          # Affiche le code retour de commande précédante
0                   # 0: La commade c'est bien exécuté et la commande obtient un resultat correcte

$> test 1 -eq 2     # Test si 1 equivaut à 2

$> echo $?          # Affiche le code retour de commande précédante
1                   # 1: la commande c'est exécuté correctement mais le résultat est mauvais
RTFM: Voir le manuel de la commade test pour voir les options et les arguments
Attention: Les nombres et les chaînes de caractères ne se traitent pas de la même manière

1- Les conditions (if/elif/else)

Les condition if elif else permettent de vérifier une/des condition(s) afin de réagir en fonction du résultat.

Syntaxe

if [ test ]
then
    commande 1
elif commande
then
    commande 2
else
    commande 3
fi


#!/bin/bash
#

if [ "$1" -eq 1 ]
then
        echo "Le premier argument est 1"
else
        echo "Le premier argument n'est pas 1"
fi

Exemple: opération_conditionnelle/if/if_1.sh

Il est possible d’exécuter des commandes suite à un test.


#!/bin/bash
#

if [ "$1" -eq 1 ]
then
        ls -l
else
        echo "RIEN"
fi

Exemple: opération_conditionnelle/if/if_2.sh

Il est possible d’effectuer plusieurs test en même temps:


#!/bin/bash
#

if [[ "$1" -gt 10 && "$1" -lt 15 ]]
then
        echo "Le nombre est compris entre 10 ( non inclus ) et 15 ( non inclus )"
elif [[ "$1" -ge 20 && "$1" -le 25 ]]
then
        echo "Le nombre est compris entre 20 (inclus) et 25 (inclus)"
else
        echo "RIEN"
fi

Exemple: opération_conditionnelle/if/if_3.sh

Vous effectuez plusieurs test en un donc la syntaxe sera [[ vérification 1 (&& ||) vérification 2 ]]

Nous avons vu que nous pouvons utiliser la commande test pour effectuer des vérifications mais il est possible d’utilisé n’importe quelle commande à la place et de réagir en fonction de son code retour.


#!/bin/bash
#

if ls \*$1 > /dev/null 2>&1
then
        echo "le code retour de la commande est:" $?
        echo "il existe des fichiers en $1"
else
        echo "le code retour de la commande est:" $?
        echo "il n'existe pas de fichier en $1"
fi

Exemple: opération_conditionnelle/if/if_4.sh

2- La boucle (for)

La boucle for permet d’effectuer une commande ou une liste de commande jusqu’à ce qu’une liste de chose soit terminé.

Syntaxe

for variable in list
do
    commande 1
    commande 2
    commande 3
done

La boucle simple permet créer une liste et d’effectuer la boucle autant de fois que la liste à été défini.


#!/bin/bash
#


for i in 5 4 3 2 1
do
        echo "il reste" $i "secondes avant la fin du monde"
        sleep 1
done

Exemple: opération_conditionnelle/for/for_1.sh

Il est possible de créer une liste depuis une variable


#!/bin/bash
#

start=1

list=${1:?Entrez un chiffre entre 1 et 9}

if [ $list -gt 9 ]
then
        echo "le chiffre est trop grand"
        exit 1
fi

for i in $(eval "echo {$start..$list}")
do
        echo "Le chiffre est:" $i
done

Exemple: opération_conditionnelle/for/for_2.sh

La force de la boucle permet de réduire la charge de travaille du script en exécutant x fois la même commande pour une liste connu.

La force de la boucle au delà du script en tant que commande dans un terminal est le meilleur ami de l’utilisateur. On appel ça une One-line commande

for i in $(ls); do sed -i "s/ip1/ip2/g" ;done

3- Le tant que (while)

Le while est un opération conditionnelle qui permet d’exécuté une commande tant qu’une condition fixé n’est pas atteinte.

Syntaxe

while condition
do
    commande 1
    commande 2
    commande 3
done


#!/bin/bash
#

id=1

while [[ $id -lt 15 ]]
do
        echo "touch fichier_"$id".txt"
        id=$(( id + 1 ))
        echo $id
done

Exemple: opération_conditionnelle/while/while_1.sh

Utiliser l’opération fonctionnelle while avec une commande fonctionne mais n’est pas cohérente dans le sens ou une commande s’exécute une fois et obtient un seul résultat (code d’erreur) là ou while attent une opération jusqu’à obtention d’un résultat.

Néanmoins des cas d’utilisation avec une commande est très utile lorsque la commande à pour but de généré plusieurs occurences:

Par exemple read.


#!/bin/bash
#

num=1

while read -r line
do
        echo "ligne $num: $line"
        num=$(( num + 1 ))
done < /etc/passwd

Exemple: opération_conditionnelle/while/while_2.sh

Le while s’exécute également en One-line pour gagné du temps.

i=1 ; while [[ $i -lt 5 ]] ; do echo "quelque chose" ;done

La force du while est la possiblité de faire des boucles infini avec possibilité de l’arrété avec une condition exécuté au sein de la boucle.

On appel ça un break


#!/bin/bash
#

secret="secret"

while :
do
        read -p "Entrez votre le mot secret:" mdp
        if [ $mdp == "$secret" ]
        then
                break
        fi

        echo "Ce n'est pas le bon mot de passe"
        echo -e "Indice: lisez bien la phrase\n"

done

echo "Vous avez trouvez le mot $secret"

Exemple: opération_conditionnelle/while/while_3.sh

Le while s’exécute en boucle et ensuite dans la boucle on vérifie une condition, si elle est vrai alors on sort de la boucle sinon elle tourne en continue

4- Les cas (case)

L’opération conditionnelle case permet de vérifié le contenu d’une condition et de réagir en fonction. Elle permet d’évité d’utilisé les autres opérations conditionnelle lorsque de nombreuses valeur peuvent être attendu en résultat.

Syntaxe

case variable in

    cas 1)
        commande 1
    ;;

    cas 2)
        commande 2
    ;;

    cas 3)
        commande 3
    ;;
esac


#!/bin/bash
#

input=${1:?Entrez un chiffre entre 1 et 5}


case $input in
        1)
                echo "Le chiffre est 1"
                ;;
        2)
                echo "Le chiffre est 2"
                ;;
        3)
                echo "Le chiffre est 3"
                ;;
        4)
                echo "Le chiffre est 4"
                ;;
        5)
                echo "Le chiffre est 5"
                ;;

        *)
                echo "Entrez une valeur entre 1 et 5"
                exit 1
                ;;
esac

Le case vérifie des modèles (pattern) afin de réagir en fonction de la valeur de la variable.

Exemple: opération_conditionnelle/case/case_1.sh

Le pattern *) inclus tous les autres types de pattern et permet de sécurisé le script lorsque le pattern ne correspond à aucun pattern prédéfini.

Il est possible de remplacer la variable par une commande.


#!/bin/bash
#

case $(pwd | cut -d "/" -f2) in
        home)
                echo "Vous êtes dans votre home"
                ;;
        usr)
                echo "Vous êtes dans /usr"
                ;;
        var)
                echo "Vous êtes dans le /var"
                ;;
        "")
                echo "Vous êtes à la racine"
                ;;
esac

Exemple: opération_conditionnelle/case/case_2.sh

Un pattern ne peut pas être NULL

Les patterns variables

Il est fortement déconseillé de mettre des variables dans les patterns des case car comme vu précédement une variable vit et il est très facile de perdre le contrôle du script en cas de mauvaise utilisation des variables.

Pour rappel: Un script DOIT être fiable, il doit s’exécuté correctement même dans le cas d’une mauvaise utilisation.
